# Сборка автономного сайдкара (без Python у пользователя)

По умолчанию ИИ-функции (умный поиск, автотеги) и скачивание через gallery-dl
работают через `sidecar/main.py` — то есть требуют установленного Python и
`pip install -r sidecar/requirements.txt`.

Чтобы этого не требовалось, сайдкар можно упаковать в один автономный
исполняемый файл. Приложение само найдёт его и перестанет звать Python.

## Как собрать

```powershell
# из корня проекта
powershell -ExecutionPolicy Bypass -File sidecar\build.ps1
```

Скрипт установит зависимости и PyInstaller, соберёт бинарник и положит его в
`sidecar\dist\fm-sidecar.exe`. Сборка идёт долго (десятки минут) — onnxruntime
большой; итоговый пакет ~300–600 МБ.

Проверить: перезапусти приложение → ⚙ Настройки → Общие → строка «ИИ-модуль»
должна сказать, что Python не требуется.

## Где приложение ищет бинарник

По порядку:

1. рядом с `furrymanager.exe` — `fm-sidecar.exe`
2. `<папка exe>\sidecar\fm-sidecar.exe`
3. `sidecar\dist\fm-sidecar.exe` (относительно рабочей папки — для `cargo tauri dev`)

Если ничего не найдено — используется `sidecar/main.py` через Python, как раньше.

## Включить в установщик

Уже включено: в `src-tauri/tauri.conf.json` папка сборки перечислена в ресурсах.

```json
"resources": {
  "../sidecar/dist": "sidecar",
  "../sidecar/main.py": "sidecar/main.py",
  "../sidecar/requirements.txt": "sidecar/requirements.txt"
}
```

Собран сайдкар — `cargo tauri build` кладёт его рядом с приложением, и
установщик становится самодостаточным. Не собран — ставится только `main.py`,
и ИИ пойдёт через Python.

### `sidecar/dist/PLACEHOLDER.txt` — не удалять

Сама сборка в git не хранится (сотни мегабайт, см. `.gitignore`), но **папка
должна существовать**: Tauri проверяет пути ресурсов в build-скрипте и падает
с `resource path ..\sidecar\dist doesn't exist` ещё до компиляции. Поэтому
`PLACEHOLDER.txt` — единственный отслеживаемый файл внутри `dist`, он держит
папку в репозитории. `build.ps1` пересоздаёт его после сборки; CI-workflow
подстраховывается отдельным шагом.

## Важные нюансы

- **Модели не вшиваются.** CLIP (~600 МБ) и WD14 (~450 МБ) по-прежнему
  скачиваются при первом использовании в кэш HuggingFace. Иначе установщик
  распух бы на гигабайт. После первой загрузки сайдкар работает офлайн.
- **UPX отключён** намеренно — он ломает onnxruntime.
- **gallery-dl** собирается со всеми подмодулями (`collect_submodules`), иначе
  экстракторы сайтов не находятся и скачивание молча не работает.
- Антивирусы иногда придираются к свежесобранным PyInstaller-бинарникам —
  это ложное срабатывание, характерное для упакованного Python.
- Собирать нужно на той ОС, для которой делается сборка (Windows → Windows).
